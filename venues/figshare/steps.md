# Figshare：出す手順

利用者が手順を求めたので、手順として書きます（cpsbvbng26-dotcom の決めごと 16 の例外）。
2026-11-18 に golden-window-resolution の稿を出したときの手順を、作品によらない形にしたものです。
Figshare の手引きの頁は、この作業の環境から届きません。
画面の名前と並びは、どの段も確かめていません。
どの段も、画面の名前は記憶によります。
欄に貼る文は [fields.md](./fields.md) にあります。

1. figshare.com に、前の稿を出したのと同じアカウントでサインインする。
2. My data（自分の項目の一覧）を開き、Create a new item を選ぶ。前の稿の新しい版にするかどうかは、先に決めておく。
3. ファイルの欄に PDF を上げる。上げたら、PDF が開けることと、頁の数が手元の PDF と同じであることを見る。
4. Title に題を貼る。
5. Authors に著者を入れる。所属の欄があっても書かない。
6. Categories で分類を選ぶ。一覧から選ぶ形で、自由には書けなかったと記憶している。
7. Item type で Preprint を選ぶ。
8. Keywords に語を順に入れる。
9. Description に要旨、状態の行、開示の段を貼る。
10. Funding の欄があれば、資金が無いことを書く。
11. References に参考文献の DOI を行ごとに貼る。前の稿の DOI を含める。
12. 関連する項目の欄があれば、前の稿を References として、GitHub のリポジトリを IsSupplementedBy として入れる。
13. License で CC BY 4.0 を選ぶ。
14. Publish の前に、必須の欄が埋まっていないという表示が出ないかを見る。
15. Publish を押す。公開すると取り消せず、ファイルを差し替えるには新しい版になる、と記憶している。
16. 公開された項目の頁に出る DOI（10.6084/m9.figshare.… の形）を写す。この番号を受け取るまで、どのリポジトリにも番号を書かない（決めごと 1）。

確かめられなかったこと：

- 必須の欄がどれか。
- 分類の一覧に何があるか。
- 関連する項目の欄の名前と、関係の種類の選び方。
- 公開したあとに直せる範囲。
